# 2025 H 题动物识别模块

## 目标

该模块面向 2025 年全国大学生电子设计竞赛 H 题“野生动物巡查系统”，识别：

1. elephant
2. tiger
3. wolf
4. monkey
5. peacock

赛题使用打印后粘贴在地貌图上的动物体态图，而不是自然场景照片。普通 COCO 权重没有完整覆盖这五个类别，因此本模块使用开放词汇 `YOLOE-26s-seg`，并把赛题官方动物体态图中的 15 个姿态作为视觉提示写入导出的 TensorRT 引擎。

## 数据链路

```text
/dev/video0
  └─ orin-camera-stream.service（唯一设备所有者）
       ├─ 8090/snapshot.jpg
       └─ 8090/stream.mjpg
            └─ vision-gateway（只读 HTTP 快照，不挂载 /dev）
                 ├─ YOLOE-26s-seg / TensorRT FP16
                 ├─ 三帧确认与短时跟踪去重
                 ├─ 8765/healthz
                 ├─ 8765/v1/detections/latest
                 ├─ 8765/v1/events
                 ├─ 8765/v1/counts
                 ├─ 8765/snapshot.jpg
                 └─ 8765/stream.mjpg
```

`vision-gateway` 不读写 MAVROS、FAST-LIO、飞控串口或电机控制接口。视觉服务失败不会直接改变飞行状态。

## 模型与性能配置

默认配置：

```text
checkpoint:       yoloe-26s-seg.pt
prompt mode:      visual
prompt examples:  每类 3 个，共 15 个
TensorRT:         FP16，batch=1，固定输入
input size:       768
target rate:      10 FPS
camera source:    1280x720 最新 JPEG 快照
confidence:       0.001（配合航拍目标几何过滤和连续 3 帧确认）
box filter:       宽/高不超过画面 70%，面积不超过画面 25%
border filter:    距离画面四边至少 0.5%，被裁切目标进入画面后再确认
tracking confirm: 连续 3 帧
tracking expiry:  丢失 8 帧
```

选择 `26s` 而不是 `26n` 的原因是当前设备为 8 GB Orin Nano，实时飞行栈空闲时仍有充足内存；`26s` 的开放词汇精度明显高于 `26n`，而计算量仍适合 10 FPS 级别的机载识别。最终输入尺寸和帧率必须以板端实测为准。

## 操作

```bash
cd /home/tfboys_nano/TYI_E100_Firmware

# 构建独立视觉镜像
./scripts/vision.sh build

# 在本机 Orin GPU 上生成设备绑定的 TensorRT 引擎
./scripts/vision.sh prepare

# 启动
./scripts/vision.sh up

# 检查相机、模型、检测 API
./scripts/vision.sh check

# 使用官方动物图和地貌图生成可复现实验集并测量精度/延迟
./scripts/vision.sh benchmark

# 查看日志
./scripts/vision.sh logs

# 停止视觉模块，不影响飞行容器
./scripts/vision.sh down
```

该服务位于 Compose `vision` profile，默认执行普通 `docker compose up -d` 时不会启动。

## 板端实测

```text
TensorRT 引擎:     FP16，静态 768，22.0 MB
引擎 SHA-256:      C324E2AFDEBF254C5616384ADC48472D5678ADA3BAFA33925A6001BB5451ABC9
常驻内存:          约 1.54-1.55 GiB
容器硬上限:        2500 MB
实时相机推理:      约 29-33 ms/帧
业务目标帧率:      10 FPS
推理能力:          约 19-25 FPS
```

最终合成压力集包含 24 幅场景、135 个目标。`confidence=0.001` 且启用航拍几何与边缘过滤时，检出 61 个目标，precision `0.3427`、recall `0.4519`，平均延迟 `47.88 ms`、P95 `58.70 ms`。对着曾产生纸巾盒边缘误报的同一场景连续运行 1150 帧后，检测数、确认事件数和取帧失败数均为 0。

该结果只证明模型、类别提示、TensorRT、相机和 API 链路可以运行。合成集中的象和猴召回率仍偏低，不能据此宣称已经达到赛题识别精度。正式使用前必须把官方动物图打印出来，用当前镜头在实际飞行高度、角度和光照下采集验证集，再决定是否调阈值或微调轻量级闭集 YOLO 模型。

## 计数边界

`/v1/counts` 中的 `sessionConfirmedTrackEvents` 只做时间维度的短时去重。无人机飞离后再次经过同一只动物，可能产生新的 track event。

赛题最终要求按网格统计。可靠的最终计数必须由任务层或地面站把检测中心、相机标定、无人机位姿和网格坐标融合后完成；不能把临时 track 数直接当作最终赛题答案。

`benchmark` 生成的合成图用于验证提示类别、旋转/亮度鲁棒性和板端性能。因为图像仍由官方素材合成，它不能代替“打印动物图、按比赛高度和现场光照实拍”的最终验证集。

## 网络与代理

下载镜像或权重时可以给单次命令设置代理。不要把实验室电脑代理地址写入 systemd、Docker daemon 或 shell profile。运行阶段完全使用板内回环地址，不依赖互联网和电脑代理。

## 预训练模型基线（2026-07-25）

本轮只测试公开预训练权重，不构造数据集，也不微调。测试输入为赛题官方
`动物体态.jpg`（15 个目标，象、虎、狼、猴、孔雀各 3 个）。

### YOLO11s-seg（COCO）

- 权重：Ultralytics 官方 `yolo11s-seg.pt`，20,669,228 bytes。
- SHA-256：
  `1CAA81C0195412EFA411B632BCFB8C184939DDDB6AE41F6A80C41B211FF257C3`。
- 15 个官方目标裁剪中，10 个存在置信度不低于 0.8 的检测，但只有 3 个检测
  的类别名与赛题目标完全一致，均为 `elephant`。
- 3 只虎均被高置信度识别为 `zebra`；狼主要识别为 `dog`；猴主要识别为
  `bear`/`dog`；孔雀只能识别为通用 `bird`。

结论：COCO 预训练模型的定位和视觉特征可复用，但其标签空间不含完整五类，
不能直接作为赛题最终分类器。它适合作为未来闭集微调的轻量分割骨干。

### Google SpeciesNet v4.0.3a + MegaDetector v5a

- SpeciesNet 分类器权重：224,393,837 bytes。
- MegaDetector 权重：280,767,041 bytes，SHA-256：
  `FE3E90E4B1955821AB7C1F88B446DC0C8CB25E109FDD1872916A55305294A5EF`。
- 官方整图检测 15 个框，和 15 个标注框在 IoU 0.5 下全部一一匹配：
  precision `1.0`、recall `1.0`、平均 IoU `0.7739`；最低检测置信度
  `0.8884`。
- 裁剪分类结果：象 3/3 为 `african elephant`（0.9957--0.9984）；虎
  3/3 为 `tiger`（0.9996--0.9998）；狼输出 `canis species` 或
  `grey wolf`（0.7775--0.8982）；猴仅稳定到 `animal`；孔雀稳定到
  `phasianidae family` 或 `pavo species`（0.6512--0.8727）。

结论：SpeciesNet/MegaDetector 是当前明显更好的公开预训练基线。检测层已经
达到本组官方静态图的 0.8 门槛；细分类层可直接可靠识别象、虎，但狼、猴、孔雀
尚不能在 0.8 阈值下全部稳定输出赛题五类。当前板端 YOLOE 服务继续保留作可回退
链路，不把 SpeciesNet 直接替换到飞行环境，也不开始微调，等待实拍验证和下一步决策。
